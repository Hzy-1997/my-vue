# 加密密钥环境配置方案

## 环境分离原则

本项目采用环境变量的方式管理敏感的加密密钥，实现了开发环境和生产环境的分离配置，既保证了开发便利性，又确保了生产环境的安全性。

## 开发环境配置

### 1. 本地开发配置

1. **创建环境变量文件**：
   - 复制 `.env.example` 文件并重命名为 `.env`
   - 在 `.env` 文件中设置开发环境的密钥

2. **开发环境密钥设置**：
   ```
   # 在.env文件中
   VITE_CRYPTO_SECRET_KEY=您的开发环境密钥
   NODE_ENV=development
   ```

3. **开发时注意事项**：
   - `.env` 文件已被添加到 `.gitignore`，不会被提交到版本控制
   - 开发团队成员可以使用相同的开发密钥，方便协作

## 生产环境配置

### 1. 生产环境密钥管理（推荐方案）

**方案A：服务器环境变量配置**

```bash
# Nginx + PM2部署示例
export VITE_CRYPTO_SECRET_KEY=您的强密钥
NODE_ENV=production

# 然后启动应用
npm run build
pm run preview
```

**方案B：CI/CD环境变量配置**

- 在GitHub Actions、Jenkins等CI/CD平台中设置环境变量
- 构建时自动注入密钥，无需在代码中存储

**方案C：Docker容器部署**

```bash
# 使用环境变量启动容器
docker run -e VITE_CRYPTO_SECRET_KEY=您的强密钥 -e NODE_ENV=production -p 80:80 your-image-name
```

### 2. 生产环境安全要求

- **必须设置密钥**：代码中已添加检查，生产环境缺少密钥会抛出错误
- **使用强密钥**：生产环境密钥应足够复杂（至少20位，包含字母、数字、特殊字符）
- **定期轮换**：建议每3-6个月更换一次生产环境密钥
- **保持前后端一致**：确保后端Node.js服务使用相同的密钥值

## 密钥管理最佳实践

1. **不同环境不同密钥**：开发、测试、预发布、生产环境应使用不同的密钥
2. **密钥备份**：安全备份生产环境密钥，防止丢失
3. **访问控制**：限制生产环境密钥的访问权限，只授予必要人员
4. **审计日志**：记录密钥使用情况，便于安全审计

## 环境变量说明

| 环境变量名 | 说明 | 开发环境 | 生产环境 |
|------------|------|----------|----------|
| VITE_CRYPTO_SECRET_KEY | 加密解密使用的主密钥 | 可选（有默认值） | 必须设置 |
| NODE_ENV | 环境标识 | development | production |

## 故障排除

1. **解密失败**：检查前后端密钥是否一致
2. **构建错误**：生产环境构建时确保已设置环境变量
3. **运行时错误**：生产环境缺少密钥会抛出明确的错误信息

## 注意事项

- **绝对不要**将生产环境密钥提交到版本控制系统
- **绝对不要**在代码注释中包含实际密钥
- **绝对不要**在前端代码中硬编码敏感信息
- 定期更新依赖库，确保使用最新的安全补丁
